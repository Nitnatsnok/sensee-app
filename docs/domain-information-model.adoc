= Доменная информационная модель клиента Sensee

Этот документ описывает предметную информационную модель Sensee на уровне доменных понятий.
Документ помогает сначала увидеть доменные сущности, а потом переходить к модулям, сценариям поведения и техническим интеграциям.

Важно::
Модель `authoring-first` (сначала ввод материала, потом карточки) уже поддержана вертикалью ввода (`shared/feature/vocabulary-editor`) и устойчивым хранением. Группировка под леммой и производные карточки пока описаны как целевое развитие и частично представлены в текущем `Practice`-срезе. Статус каждой сущности указан в таблице.

== Основные сущности

[options="header",cols="1,3,1"]
|===
|Сущность|Смысл|Статус в коде
|Lexical Entry|Слово, выражение или фраза, которую пользователь добавляет как единицу изучения|реализовано: вертикаль ввода и устойчивое хранение
|Meaning / Sense|Отдельный смысл `Lexical Entry`, не смешиваемый с другими значениями|реализовано в `vocabulary-editor/domain`
|Contextual Application|Отдельное контекстное употребление, устойчивое сочетание или смысловой вариант использования|реализовано через структурную `StudiedSentence`
|Grammar Cue|Часть речи, форма, управление, предлог или другое грамматическое уточнение|реализовано в `shared/grammar/domain`
|Meaning Candidate|Неподтверждённый смысл, предложенный AI-подсказкой или другим внешним источником|реализовано через границу AI-интеграции, ADR-005
|Confirmed Meaning|Смысл, который пользователь подтвердил и который можно использовать для дальнейшего создания карточек|реализовано: выбор и есть подтверждение, ADR-001
|Derived Learning Card|Учебная карточка, производная от подтверждённого материала|частично представлено в текущем `Practice`-срезе
|Review State|Состояние повторения и история оценки учебного артефакта|реализовано в текущем `Practice`-срезе
|===

== Связи между сущностями

[options="header",cols="1,3"]
|===
|Связь|Описание
|`Lexical Entry` -> `Meaning / Sense`|Одна лексическая запись может иметь несколько смыслов
|`Meaning / Sense` -> `Contextual Application`|Один смысл может иметь несколько контекстных употреблений
|`Meaning / Sense` -> `Grammar Cue`|К смыслу могут быть привязаны грамматические признаки и ограничения употребления
|`Meaning Candidate` -> `Confirmed Meaning`|Кандидат становится каноническим содержанием только после подтверждения
|`Confirmed Meaning` -> `Derived Learning Card`|Из подтверждённого материала создаются учебные карточки и другие упражнения
|`Derived Learning Card` -> `Review State`|Состояние повторения относится к учебному артефакту, а не к самому значению
|===

== Ключевые правила модели

* Карточка не является источником истины для смысла.
* AI-подсказка не становится каноническим содержанием автоматически.
* `Grammar Cue` и `Contextual Application` моделируются отдельно, а не теряются внутри текстового описания; полный перечень частей речи, категорий и форм ведётся в `pos-and-forms.adoc`.
* `Review State` не должен смешиваться с лексическим значением.
* Добавление новых упражнений не должно требовать смены исходной модели.
