# Поведенческие сценарии (Gherkin)

Каталог содержит `.feature`-файлы для сценариев из `docs/arc42/sections/06_runtime_view.adoc`.

## Назначение

- Зафиксировать ожидаемое поведение уже реализованных сценариев в виде, пригодном для ручной верификации и будущих автотестов (`early-stage`: BDD-раннер к `.feature` ещё не подключён, реестр в arc42 §11).
- Отделить реализованное поведение (`@implemented`) от планируемого (`@planned`), чтобы документация не выдавала целевую архитектуру за текущую.
- Удерживать связь между шагами и реальными классами/файлами через блок `Источники реализации:` в каждом файле.

## Соглашения

- Ключевые слова `Gherkin` — на русском (`# language: ru`).
- Код-термины (`DeckPracticeLogic`, `PracticeReviewRepository`, `ScreenConfig`, ...) оставляются в исходном виде в обратных кавычках, как и в остальной документации.
- Один `.feature` покрывает одну поведенческую область — один runtime-сценарий из `docs/arc42/sections/06_runtime_view.adoc`; внутри файла обычно несколько `Сценарий:`, по одному на конкретное поведение. Это сохраняет трассировку `arc42 ↔ feature` прозрачной.
- Допустимы ровно два статус-тега: `@implemented` (сценарий описывает текущее поведение кода) и `@planned` (целевое поведение, которого в коде ещё нет). Третьего уровня статуса нет; отложенность с нюансом фиксируется в `docs/backlog/`, а не отдельным тегом.
- Тегирование статуса: если файл содержит только один статус, тег можно ставить на уровне `Функция:`. Если в файле смешаны реализованные и планируемые сценарии, feature-level статус не используется: каждый сценарий получает свой `@implemented` или `@planned`. Остальные теги (`@navigation`, `@vocabulary`, ...) — тематические, не статусные.

## Когда обновлять

- Проектирование новой или переосмысленной пользовательской возможности начинается здесь: до кода добавляется новый `@planned` сценарий или расширяется существующий. Шаги должны быть проверяемы вручную и пригодны для будущего автотеста.
- Если меняется реализованный пользовательский сценарий (например, появляется `Undo`, пересобирается верхняя панель, меняется соответствие свайпа и рейтинга) — обновить соответствующий `@implemented` сценарий вместе с кодом.
- Если `planned` сценарий начинает реализовываться — постепенно переносить шаги в `@implemented` и сверять с фактическим кодом.
- Сценарии должны оставаться согласованы с `docs/arc42/sections/06_runtime_view.adoc`. При расхождении правится тот источник, который отстал от кода.
