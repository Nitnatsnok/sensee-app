# Поведенческие сценарии (Gherkin)

Каталог содержит поведенческие спецификации клиентских user-flow в формате `Gherkin` (русская локализация ключевых слов). Один `.feature` файл — один runtime-сценарий из `docs/arc42/sections/06_runtime_view.adoc`.

## Назначение

- Зафиксировать ожидаемое поведение уже реализованных flow в виде, пригодном для ручной верификации и будущих автотестов.
- Отделить реализованное поведение (`@implemented`) от планируемого (`@planned`), чтобы документация не выдавала целевую архитектуру за текущую.
- Удерживать связь между шагами и реальными классами/файлами через блок `Источники реализации:` в каждом файле.

## Соглашения

- Ключевые слова `Gherkin` — на русском (`# language: ru`).
- Код-термины (`DeckPracticeLogic`, `PracticeReviewRepository`, `ScreenConfig`, ...) оставляются в исходном виде в backticks, как и в остальной документации.
- Один `.feature` соответствует одному runtime-сценарию из arc42, чтобы трассировка `arc42 ↔ feature` оставалась прозрачной.
- Допустимы ровно два статус-тега: `@implemented` (сценарий описывает текущее поведение кода) и `@planned` (целевое поведение, которого в коде ещё нет). Третьего тира статуса нет; отложенность с нюансом фиксируется в `docs/evolution-backlog.adoc`, а не отдельным тегом.
- Тегирование статуса: статус-тег ставится на уровне `Функция:` (file-level) и задаёт статус по умолчанию для всех сценариев файла; отдельный сценарий, который отклоняется от этого статуса, помечается своим статус-тегом на уровне сценария (на практике — `@planned` в `@implemented`-файле). Остальные теги (`@navigation`, `@vocabulary`, ...) — тематические, не статусные.

## Когда обновлять

- Проектирование новой или переосмысленной пользовательской фичи начинается здесь: до кода добавляется новый `@planned` сценарий или расширяется существующий. Поведение описывается тщательно, затем реализуется через тесты (см. `Tests and verifiability` в корневом `AGENTS.md`).
- Если меняется реализованный user-flow (например, появляется `Undo`, пересобирается top bar, меняется маппинг свайп → рейтинг) — обновить соответствующий `@implemented` сценарий вместе с кодом.
- Если `planned` сценарий начинает реализовываться — постепенно переносить шаги в `@implemented` и сверять с фактическим кодом.
- Сценарии должны оставаться согласованы с `docs/arc42/sections/06_runtime_view.adoc`. При расхождении правится тот источник, который отстал от кода.
