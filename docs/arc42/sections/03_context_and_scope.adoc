= Контекст и границы

== Бизнес-контекст

Клиентские приложения Sensee являются пользовательской точкой входа в продукт для внесения, уточнения и последующего изучения английских слов и выражений. На уровне продуктового замысла клиент должен поддерживать внесение лексического материала, разделение смыслов с AI-подсказками, фиксацию контекстных употреблений и грамматических уточнений, а также создание связанных учебных карточек на основе подтверждённого материала.

В текущей фазе реализованный клиентский срез покрывает общий app shell, навигацию, practice-сценарий (deck + home + card detail), library catalog с подпиской на сервисные наборы, profile-настройки и authoring-вертикаль capture (внесение -> AI/curated-подсказки -> мультивыбор смыслов -> подтверждение с устойчивым сохранением; граница лексической верификации реализована и подключена к живому capture в двух узких ролях — pre-AI grounding в prompt и silent post-AI фильтр качества примеров). Группировка под леммой, captured deck projection и form-variant cards для неправильных глаголов уже реализованы в data/domain слое; дальнейшая продуктовая эволюция остаётся в UI-курировании (`LemmaDetail`/`DeckDetail`, навигация по семье, claim части набора и курирование колод).

Контекстная схема поддерживается в `LikeC4 view` `index` в `docs/c4/`. Платформенные артефакты и deployable targets вынесены отдельно в `LikeC4 deployment view` `deployment`.

== Внешние участники и системы

[options="header",cols="1,3,3"]
|===
|Участник / система|Тип|Взаимодействие
| Пользователь | Основной актор | Запускает приложение, открывает основные разделы, в текущей реализации проходит practice deck; в целевом продуктовом контуре вносит и уточняет лексический материал
| Platform services | Внешняя зависимость | Предоставляют lifecycle, UI runtime, браузерный/desktop/mobile контекст и platform-specific capabilities
| SQLDelight local storage module | Локальная инфраструктура | Даёт shared persistence-модуль, platform drivers и локальное хранение текущего клиентского среза: practice/SRS-state, настройки, library catalog и подтверждённый лексический материал
| Fixture-backed network boundary | Внутренняя клиентская инфраструктура | Использует `shared/core/network` и `shared/core/mock-backend`, чтобы реализованные сценарии на фикстурах шли через нормальную `HttpClient`-границу без live backend
| AI/TTS/verification provider APIs | Внешняя зависимость | Подключаются через клиентские границы `shared/ai/*`, `shared/tts/*` и `shared/verification/*`: LLM/TTS-провайдеры, Free Dictionary, Datamuse и LanguageTool доступны только через seam-адаптеры; без ключей или при недоступности провайдера клиент использует curated coverage там, где она есть, либо деградирует к ручному вводу
| Future Sensee backend | Отложенная внешняя система | В будущем будет поставлять API для синхронизации, профиля, серверного каталога и более полного продуктового сценария
|===

== Границы ответственности клиента

Клиент включает в себя:

* platform entrypoints в `apps/androidApp`, `apps/desktopApp`, `apps/webApp`, `apps/iosFramework` и `apps/iosApp`;
* shared app shell в `shared/app-shell`;
* feature presentation modules в `shared/feature/*/presentation/*`;
* practice domain/data/schema modules в `shared/feature/practice/domain`, `shared/feature/practice/data` и `shared/feature/practice/database-schema`;
* reusable UI-библиотеки в `shared/ui/*`;
* component/navigation infrastructure в `shared/core/decompose`; DI wiring через Metro-граф `AppGraph` в `shared/app-shell`;
* shared persistence-модуль `shared/database`;
* shared settings modules в `shared/settings/*`;
* grammar taxonomy modules в `shared/grammar/*`;
* AI-enrichment seam в `shared/ai/*`, lexical verification seam в `shared/verification/*` и TTS seam в `shared/tts/*`;
* network и mock-backend boundaries в `shared/core/network` и `shared/core/mock-backend`;
* SRS-библиотеки в `shared/srs/*`.

Клиент не включает в себя:

* live backend-интеграцию в основном practice-сценарии;
* server-side разделения смыслов с AI-поддержкой и подтверждения смыслов;
* production authentication, sync и profile-сценарий;
* server-side AI-оркестрацию, серверную агрегацию словарей, коммерческие словарные интеграции и серверное хранение секретов.

== Контекстные правила

* Клиентский arc42 фиксирует только client-side решения и ограничения текущего состояния репозитория.
* Реализованный клиентский срез и целевой продуктовый контур должны описываться раздельно: implemented — как факт, planned — как эволюция.
* Подключённые shared-модули описываются как часть текущего implemented slice только там, где это подтверждается кодом.
* Подготовленные и будущие интеграции с live backend, серверной оркестрацией и более широким продуктовым сценарием описываются отдельно как эволюция, а не как уже реализованное поведение.
