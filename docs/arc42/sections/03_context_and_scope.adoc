= Контекст и границы

== Бизнес-контекст

Клиентские приложения Sensee являются пользовательской точкой входа в продукт для внесения, уточнения и последующего изучения английских слов и выражений. На уровне продуктового замысла клиент должен поддерживать внесение лексического материала, AI-assisted разделение смыслов, фиксацию контекстных употреблений и грамматических уточнений, а также создание связанных учебных карточек на основе подтверждённого материала.

В текущей фазе реализованный клиентский срез покрывает общий app shell, навигацию, practice flow (deck + home + card detail), library catalog с adoption, profile-настройки и authoring-вертикаль capture (внесение → AI-enrichment → мультивыбор смыслов → durable confirm). Дальнейшая продуктовая эволюция (lemma-семья, деривация derived-карточек, курирование колод) остаётся планируемой и задаёт продуктовый фокус архитектуры. Реализованный срез уже отражает этот замысел: клиент хранит учебные смыслы раздельно и не смешивает текст карточки, значение, пример, транскрипцию, произношение и review state.

Контекстная схема поддерживается в view `index` в `docs/c4/`. Платформенные артефакты и deployable targets вынесены отдельно в view `deployment_targets`.

== Внешние участники и системы

[options="header",cols="1,3,3"]
|===
|Участник / система|Тип|Взаимодействие
| Пользователь | Primary actor | Запускает приложение, открывает основные разделы, в текущей реализации проходит practice deck; в целевом продуктовом контуре вносит и уточняет лексический материал
| Platform services | External dependency | Предоставляют lifecycle, UI runtime, браузерный/desktop/mobile контекст и platform-specific capabilities
| SQLDelight local storage module | Local infrastructure | Даёт shared persistence-модуль, platform drivers и локальное хранение текущего client slice: practice/SRS-state, настройки, library catalog и подтверждённый лексический материал
| Fixture-backed network boundary | Internal client infrastructure | Использует `shared/core/network` и `shared/core/mock-backend`, чтобы реализованные fixture-backed flow шли через нормальный `HttpClient` boundary без live backend
| AI/TTS provider APIs | External dependency | Подключаются через клиентские seams `shared/ai/*` и `shared/tts/*`; без ключей или при недоступности провайдера клиент деградирует к offline/manual path
| Future Sensee backend | Deferred external system | В будущем будет поставлять API для синхронизации, профиля, серверного каталога и более полного продуктового workflow
|===

== Границы ответственности клиента

Клиент включает в себя:

* platform entrypoints в `apps/androidApp`, `apps/desktopApp`, `apps/webApp`, `apps/iosFramework` и `apps/iosApp`;
* shared app shell в `shared/app-shell`;
* feature presentation modules в `shared/feature/*/presentation/*`;
* practice domain/data/schema modules в `shared/feature/practice/domain`, `shared/feature/practice/data` и `shared/feature/practice/database-schema`;
* reusable UI-библиотеки в `shared/ui/*`;
* component/navigation infrastructure в `shared/core/decompose`; DI wiring через Metro-граф `AppGraph` в `shared/app-shell`;
* shared persistence-модуль `shared/database`;
* shared settings modules в `shared/settings/*`;
* grammar taxonomy modules в `shared/grammar/*`;
* AI-enrichment seam в `shared/ai/*` и TTS seam в `shared/tts/*`;
* network и mock-backend boundaries в `shared/core/network` и `shared/core/mock-backend`;
* SRS-библиотеки в `shared/srs/*`.

Клиент не включает в себя:

* live backend-интеграцию в основном practice flow;
* server-side AI-assisted disambiguation и подтверждение смыслов;
* production authentication, sync и profile workflow;
* server-side AI-оркестрацию, внешние словарные источники и серверное хранение секретов.

== Контекстные правила

* Клиентский arc42 фиксирует только client-side решения и ограничения текущего состояния репозитория.
* Реализованный client slice и целевой продуктовый контур должны описываться раздельно: implemented — как факт, planned — как эволюция.
* Подключённые shared-модули описываются как часть текущего implemented slice только там, где это подтверждается кодом.
* Подготовленные и будущие интеграции с live backend, AI-assisted authoring и richer product flow описываются отдельно как эволюция, а не как уже реализованный runtime.
