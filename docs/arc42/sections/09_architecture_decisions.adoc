= Архитектурные решения

В этом разделе собраны только архитектурно значимые решения. Чтобы не перегружать основной текст arc42, сами решения фиксируются как отдельные ADR в `docs/adr/`, а здесь остаётся центральный индекс. Связанные схемы эволюции клиента и продуктовых сценариев поддерживаются в `docs/c4/`, включая `vocabulary_capture_flow`.

Стратегические решения высокого уровня по-прежнему кратко отражаются в `04_solution_strategy.adoc`; этот раздел нужен для прослеживаемости: почему решение принято, какие альтернативы рассматривались и какие последствия оно несёт.

== Правила ведения решений

* В ADR фиксируются только важные, дорогостоящие, рискованные или архитектурно масштабные решения.
* Для каждого решения важно хранить не только итог, но и контекст, альтернативы и последствия.
* Решения со статусом `Proposed` не должны описываться в runtime или building block view как уже реализованные.
* Если решение локально и касается только одного строительного блока, его допустимо документировать рядом с этим блоком, а не выносить в центральный индекс.
