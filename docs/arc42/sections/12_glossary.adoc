[[client-section-glossary]]
= Глоссарий

Глоссарий фиксирует термины с особым смыслом в Sensee: доменные понятия, имена из кода и несколько проектных архитектурных терминов. Очевидные общеинженерные слова не дублируются здесь без необходимости.

[options="header",cols="1,3"]
|===
|Термин|Определение
|Client arc42|Отдельный arc42-документ, описывающий только клиентские приложения Sensee
|Shared Client Core|Общая KMP-часть клиента, содержащая shared app shell, feature UI и reusable библиотеки
|App Shell|Модуль `shared/app-shell`, собирающий общую тему, root UI и стартовую навигацию приложения
|RootComponent|Корневая Decompose-компонента, управляющая child stack приложения
|StartupComponent|Root-level компонент стартового экрана перед открытием `PrimaryShellComponent`
|PrimaryShellComponent|Decompose-компонент базовой primary navigation shell
|Primary Navigation Shell|Основная навигационная оболочка с разделами `Home`, `Practice`, `Library`, `Vocabulary Editor` и `Profile`
|Section Component|Feature-level компонент раздела, который владеет своим набором `ScreenConfig`
|Capture|Внесение пользователем нового слова или выражения с последующим уточнением смыслов, контекстов и грамматических подсказок
|Authoring-first|Приоритет ввода и структурирования пользовательского материала перед созданием производных карточек
|Sense-first model|Модель, где отдельный смысл является центральной единицей обучения, а карточка создаётся как производный артефакт
|Enrichment|Обогащение введённого материала подсказками: варианты смыслов, контексты, grammar cues и другие данные-кандидаты
|AI/TTS Provider|Поставщик AI- или TTS-возможностей, выбираемый через настройки и подключаемый через `shared/ai/*` или `shared/tts/*`
|Adoption|Добавление сервисного набора в личный каталог пользователя; сейчас поддержано для набора целиком, частичное добавление планируется
|Learning Deck|Переиспользуемый swipeable карточный UI из `shared/ui/learning-deck`
|Lexical Entry|Исходное слово, выражение или фраза, которое пользователь добавляет в систему как единицу изучения
|Sense|Отдельное значение слова или выражения, которое не должно смешиваться с другими значениями той же lexical entry
|Sense Candidate|Неподтверждённый смысл или вариант интерпретации, предложенный AI-подсказкой или другим внешним источником
|Confirmed Sense|Смысл, который прошёл явное подтверждение пользователем и может использоваться как источник для учебных артефактов
|Contextual Application|Отдельное контекстное употребление, устойчивое сочетание или вариант использования с дополнительным смысловым оттенком
|Entry Status|Статус `LexicalEntry`: `Draft` (захвачено, возможно обогащено, но не подтверждено) или `Confirmed` (есть подтверждённые `Sense`, материал пригоден для каталога и практики). Расширенный жизненный цикл (`InRefinement`/`HasCandidates`) отложен до EB-6
|Catalog Origin|Происхождение материала в каталоге: собственный материал пользователя (`captured`/`adopted`) или сервисный набор. Это определяет, можно ли отделить добавленный набор от личного каталога
|Service Set|Курируемый набор записей/карточек, приходящий через клиентскую границу каталога; добавляется в собственный каталог целиком или частично
|NavigationDispatcher|Контракт распространения навигации: `open(config)`/`back()` с подъёмом запроса по цепочке `local -> parent` и результатом `NavigationRequestStatus`
|ScreenConfig|Сериализуемая конфигурация целевого экрана раздела (например `PracticeConfig`, `LibraryConfig`); живёт в `presentation/navigation-api`, отделена от component-hosting API (ADR-003)
|Сессия практики по выборке|Планируемое расширение контракта practice: запуск сессии по произвольному due-подмножеству, а не только по готовому `Deck`
|Grammar Cue|Структурированное грамматическое уточнение, например часть речи, форма слова, управление или используемый предлог
|Derived Learning Card|Учебная карточка, производная от подтверждённого лексического материала, а не первичный источник смысла
|Practice Flow|Текущий пользовательский срез Practice: загрузка deck из каталога Library, прохождение deck и обновление SRS-состояния
|Practice Review Repository|Feature-owned граница `PracticeReviewRepository`, через которую presentation logic отправляет результаты review; deck content приходит через `CatalogRepository`
|AI-assisted learning|Продуктовая идея Sensee: AI должен помогать объяснениями, подсказками и примерами, но не подменять базовую учебную модель
|Сегрегация смыслов|Разделение учебных понятий карточки: `front`, `back`/meaning, example, transcription, review state и будущие AI-результаты имеют разные ответственности
|UserSettingsScope|Область хранения пользовательских настроек: `Device` сейчас и `User` для будущей синхронизации после авторизации
|Anti-corruption mapping|Преобразование внешнего DTO в доменную модель на границе интеграции, чтобы модель провайдера не протекала в feature-домен
|Versioned contract|Контракт запроса/ответа с явной версией DTO; версия нужна для несовместимых изменений формата, а не для каждой новой опции
|EvidenceSet|Контейнер per-source наблюдений одного факта в верификации (`LexicalVerificationReport`): несколько провайдеров могут ответить на один и тот же вопрос, `consensus` отдаёт согласованное значение либо `null`, `hasConflict` сигнализирует о расхождении. Для nullable `T` согласованный `null` неотличим от «нет консенсуса» — пара с `hasConflict` снимает неоднозначность
|LicensePolicy|License-метаданные источника верификации, два несжимаемых флага: `usableAsLlmContext` (можно ли передавать фрагмент в LLM-prompt как evidence) и `storeContentAllowed` (можно ли класть ответ в персистентный L2-кэш). Дефолт — самый строгий (`false`/`false`), opt-in per-adapter; fail-closed для незарегистрированных источников
|PlatformEnvironment|Абстракция платформенного окружения, передаваемая в shared app shell при запуске приложения
|Persistence Module|`shared/database` с SQLDelight schema и platform-specific driver factories
|SRS Libraries|Набор модулей `shared/srs/*`, содержащих модели, engine и FSRS-реализацию
|Fixture-backed Integration|Текущая интеграция через `shared/core/network` и `shared/core/mock-backend`, которая сохраняет клиентские границы без live backend
|Prepared Foundation|Существующий модуль foundation-уровня, который ещё не образует основной пользовательский сценарий
|Implemented Client Slice|Текущий реально работающий пользовательский срез: запуск, навигация, practice (deck/home/card detail), library catalog + adoption, profile AI/TTS/App/Learning-настройки и capture-вертикаль
|Planned Integration|Будущая интеграция live backend, sync, profile-сценария и server-side AI, которая ещё не подключена к основному UI-сценарию
|===
