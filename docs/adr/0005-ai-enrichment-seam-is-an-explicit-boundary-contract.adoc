= ADR-005: Граница AI-enrichment — явный versioned contract с anti-corruption mapping
:revdate: 2026-05-17

Статус:: Accepted
Дата:: 2026-05-15
Ответственные:: Konstantin Apukhtin
Драйверы решения:: Maintainability (QG-3: смена провайдера без переписывания feature), Reliability (FS-1/FS-2: деградация и неоднозначность как явные состояния), Functional Suitability (candidate-слой ADR-001 как реальный артефакт, не «будущий прямоугольник»)

Контекст::
ADR-001 фиксирует, что AI-подсказки — это кандидаты, а не каноническое содержание. Без явного контракта границы это «будущий прямоугольник»: вызов конкретного AI-SDK прямо из feature, преобразование сырого AI-текста в UI-поля, протечка модели провайдера в домен и семантическое искажение.

Решение::
AI-enrichment оформлен как **явный версионируемый клиентский контракт** за границей, совместимой с будущим backend. Feature/UI зависят только от собственного домена; запрос/ответ — отдельные versioned DTO; между DTO и доменом обязательно **anti-corruption mapping** в candidate-модель. Контракт не зависит от провайдера; недоступность или частичный ответ — явное состояние (деградация в ручной режим), а не исключение.

Модель ответа единая и не зависит от типа ввода (слово/фраза/идиома) и языка ввода: `availability` + список смыслов-кандидатов. Форму смысла и инвариант грамматики здесь не дублируем — канон в ADR-001, `docs/scenarios/vocabulary-capture.feature` и `docs/pos-and-forms.adoc`. Конфигурация провайдера — ограниченный выбор, не свободный ввод (провайдер из списка → его базовый URL; модель из списка API провайдера с офлайн-fallback); граница предоставляет перечисление моделей; ключи device-scoped, вводятся скрытым полем дизайн-системы. Поле версии DTO — задел на развитие, не история миграции.

Альтернативы::
* Вызывать AI-SDK провайдера напрямую из feature. Отклонено: провайдер протекает в домен, мок/деградацию/тестируемость не изолировать.
* Преобразовывать сырой AI-ответ в UI-поля без candidate-домена. Отклонено: разрушает происхождение данных и объяснимость (ADR-001), смешивает смыслы.
* Жёстко зашить одного провайдера. Отклонено: vendor lock-in на архитектурном уровне.

Последствия (реализованные, 2026-05-17)::
* В коде `shared/ai/{core,curated-enrichment,llm,integration}`: контракт не зависит от провайдера и feature-домена, curated enrichment работает без ключа для покрытых лемм, OpenAI-совместимый LLM используется при настроенном ключе, маршрутизация идёт по настройкам, деградация наблюдаема. Anti-corruption (`EnrichmentSuggestion → Sense`) живёт в `shared/lexicon/enrichment`; Vocabulary Editor добавляет `SenseCandidate` только как authoring/selection wrapper. `HttpClient` — app-синглтон на реальном per-platform движке (best practice Ktor), отделён от mock-движка. Покрыто тестами на границе.

Последствия (ожидаемые)::
* Провайдера можно заменить или подменить mock-реализацией, не трогая feature/домен; curated-first routing остаётся внутри `shared/ai/integration`.
* Цена: versioned contract + mapping-слой и контрактные тесты на границе.
