= Доменная информационная модель клиента Sensee

Этот документ описывает предметную информационную модель Sensee на уровне доменных понятий.
Документ помогает сначала увидеть доменные сущности, а потом переходить к модулям, сценариям поведения и техническим интеграциям.

Важно::
Модель `authoring-first` (сначала ввод материала, потом карточки) уже поддержана вертикалью ввода (`shared/feature/vocabulary-editor`) и устойчивым хранением. Группировка под леммой, captured deck projection и карточки форм неправильных глаголов реализованы в data/domain слое; полноценная UI-навигация по семье и курирование остаются развитием. Статус каждой сущности указан в таблице.

== Основные сущности

[options="header",cols="1,3,1"]
|===
|Сущность|Смысл|Статус в коде
|Lexical Entry|Слово, выражение или фраза, которую пользователь добавляет как единицу изучения|реализовано: нейтральная модель в `shared/lexicon/domain`, write lifecycle в `vocabulary-editor`
|Sense|Отдельный смысл `Lexical Entry`, не смешиваемый с другими значениями|реализовано в `shared/lexicon/domain`
|Contextual Application|Отдельное контекстное употребление, устойчивое сочетание или смысловой вариант использования|реализовано через структурную `StudiedSentence`
|Grammar Cue|Часть речи, форма, управление, предлог или другое грамматическое уточнение|реализовано в `shared/grammar/domain`
|Sense Candidate|Неподтверждённый смысл, предложенный AI-подсказкой или другим внешним источником|реализовано через границу AI-интеграции, ADR-005
|Confirmed Sense|Смысл, который пользователь подтвердил и который можно использовать для дальнейшего создания карточек|реализовано: выбор и есть подтверждение, ADR-001
|Derived Learning Card|Учебная карточка, производная от подтверждённого материала|реализовано для captured deck projection и form-variant cards; расширенные UI/detail-сценарии planned
|Review State|Состояние повторения и история оценки учебного артефакта|реализовано в текущем `Practice`-срезе
|===

== Связи между сущностями

[options="header",cols="1,3"]
|===
|Связь|Описание
|`Lexical Entry` -> `Sense`|Одна лексическая запись может иметь несколько смыслов
|`Sense` -> `Contextual Application`|Один смысл может иметь несколько контекстных употреблений
|`Sense` -> `Grammar Cue`|К смыслу могут быть привязаны грамматические признаки и ограничения употребления
|`Sense Candidate` -> `Confirmed Sense`|Кандидат становится каноническим содержанием только после подтверждения
|`Confirmed Sense` -> `Derived Learning Card`|Из подтверждённого материала создаются учебные карточки и другие упражнения
|`Derived Learning Card` -> `Review State`|Состояние повторения относится к учебному артефакту, а не к самому значению
|===

== Ключевые правила модели

* Карточка не является источником истины для смысла.
* AI-подсказка не становится каноническим содержанием автоматически.
* `Grammar Cue` и `Contextual Application` моделируются отдельно, а не теряются внутри текстового описания; полный перечень частей речи, категорий и форм ведётся в `pos-and-forms.adoc`.
* `Review State` не должен смешиваться с лексическим значением.
* Добавление новых упражнений не должно требовать смены исходной модели.
